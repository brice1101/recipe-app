# Recipe Book

A personal recipe manager build with vanilla PHP, SQLite, and plain HTML/CSS

---

## Features

- Add, edit, and delete recipes with title, cuisine, instructions, ingredients, and an optional photo
- Filter and search by cuisine, cooked status, or keyword (matches title and ingredient names)
- Mark recipes as cooked with a toggl button that updates instantly via fetch
- Star ratings from 1 to 5
- Image uploads with server-side MIME validation and randomised filenames
- Ingredient deduplication - shared ingredients are stored once and reused across recipes

## Requirements

- PHP 8.1 or higher
- The following PHP extensions enabled: ```pdq_sqlite```, ```gd```, ```fileinfo```
- Composer (for autoloading)

Check that required extensions are active:

```bash
php -m | grep -E 'pdo_sqlite|gd|fileinfo'
```
If any are missing, uncomment the relevant lines in php.ini

## Getting started

1. Clone the repository

```bash
git clone https://github.com/brice1101/recipe-app.git
cd recipe-book

2. Install the autoloader

composer install

3. Create the database and seed sample data

```bash
php setup_dp.php
```

This creates ```config/recipes.sqlite``` and inserts sample recipes

4. Start the development server

```bash
php -S localhost:8000 -t public
```

Open http://localhost:8000 in your browser

## Routes

| Method | URI | Description |
| --- | --- | --- |
| GET | ```/``` | Redirects to ```/recipes |
| GET | ```/recipes``` | Recipe list - accepts ```?search=```, ```?cuisine=```, ```?cooked=``` |
| GET | ```/recipes/create``` | New recipe form |
| POST | ```/recipes``` | Store new recipe |
| GET | ```/recipes/{id}``` | Recipe detail page |
| GET | ```/recipes/{id}/edit``` | Edit form |
| POST | ```/recipes/{id}/edit``` | Update recipe |
| POST | ```/recipes/{id}/delete``` | Delete recipe and its image |
| POST | ```/recipes/{id}/toggle-cooked``` | Toggle cooked flag - returns ```{"cooked": true|false}``` |

HTML forms only support GET and POST, so mutations that would conventionally use PUT/PATCH/DELETE are handles as POST requests to dedicated sub-paths

## Database schema

```sql
recipes (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    title        TEXT    NOT NULL,
    cuisine      TEXT    NOT NULL DEFAULT '',
    instructions TEXT    NOT NULL DEFAULT '',
    rating       INTEGER CHECK(rating IS NULL OR (rating >= 1 AND rating <= 5)),
    cooked       INTEGER NOT NULL DEFAULT 0,
    image_path   TEXT
)

ingredients (
    id   INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL UNIQUE
)

recipe_ingredients (
    recipe_id     INTEGER REFERENCES recipes(id)     ON DELETE CASCADE,
    ingredient_id INTEGER REFERENCES ingredients(id) ON DELETE CASCADE,
    PRIMARY KEY (recipe_id, ingredient_id)
)
```

Foreign key enforcement is enabled at connection time via ```PRAGMA foreign_keys = ON```, so cascade delete works correctly

## Configuration

The app has no ```.env``` file - the only path that matters is the database location, hardcoded in ```src/Database/Database.php``` as ```config/recipes.sqlite```. The ```config/``` directory sits outside ```public/``` so the database file is never accessible over HTTP

Uploaded images are stored in ```public/uploads/``` with random hex filenames generated by ```random_bytes(16)```, making them unguessable. The original filename and extension are discarded; the real MIME type is detected from file bytes using PHP's ```finfo``` extension

## Running the model tests

After running ```setup_db.php```, you can verify the model layer against the live database:

```bash
php test_models.php
```

The script exercises every method on ```Recipe``` and ```Ingredient``` - reads, filters, creates, updates, toggles, syncs, ingredients, and deletes - and prints a pass/fail for each

## Extending the app

Some natural next steps:
- User accounts - add a ```users``` table and session-based auth so each user sees only their own recipes
- Pagination - ```Recipe::all()``` returns everything: add ```LIMIT```/```OFFSET``` for large collections
- Meal planner - a ```meal_plan``` table linking recipes to calendar days
- Import/Export - JSON or CSV export of recipe collection
- Unit quantities on ingredients - extend ```recipe_ingredients``` with a ```quantity``` and ```unit``` column
